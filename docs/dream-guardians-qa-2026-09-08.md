# 浮光守卫 · 运行、奖池与难度检查

日期：2026-09-08。检查基线为 2.0，随机掉券功能加入后的复核版本为 2.1。

## 已确认且尚未调整的问题

### 1. 第一关缺少持续操作的必要性

在覆盖较好的三个落脚点部署三名 Lv.1、I 阶萤巡，之后不升级、不增援、不使用道具、不升级工坊：约 131 秒满血通关，击败 39 只怪物，结余 927 金币。浏览器中的真实部署操作与战斗引擎模拟均复现了这一结果。

这说明增加怪物数量并没有产生相应的战斗压力。建议下一轮调整低费单体守卫的早期输出和中后波压力，让增援、减速、范围伤害与升级有作用，而不是要求抽到高星角色才能通关。

相关实现：`games/dream-guardians/js/balance-v2.js`、`games/dream-guardians/js/flow-v2.js`。

### 2. 后期金币明显溢出，工坊升级在初关回本偏慢

使用一套按覆盖和伤害收益布阵、持续购买升级的自动策略，后六关仍出现大量剩余金币。第九关结余 4,246，第十关结余 4,789。这个结果属于特定自动策略，不代表每一种玩家打法，但足以提示整体经济需要重新校准。

工坊第一次升级花费 90 金币，每六秒额外产六金币，回本约需 90 秒；第二次升级花费 150，额外每六秒八金币，回本约需 112.5 秒。第一关总时长约 131 秒，稍晚升级很难在本关体现收益。

建议同时调整波次压力、战斗升级价值、工坊回本与后期资源消耗，不单独削减金币奖励。

### 3. 战斗侧栏按钮过窄

1280 像素桌面视口下，部署守卫后侧栏的升级、目标、出售三个按钮挤在同一行，实际宽约 56–58 像素、高约 80 像素。中文标签大量换行，影响操作辨认。建议改为纵向排列或让主按钮独占一行。

页面切换保留旧滚动位置在早先截图中表现为顶部信息不完整，但本轮从桌面末关卡片进入的复测没有复现，暂列为手机长页面的待复核项，不记作稳定复现的问题。

相关实现：`games/dream-guardians/style.css`、`games/dream-guardians/refresh-v2.css`、`games/dream-guardians/js/app.js`。

## 已恢复的环境问题

原本的本地 8080 预览服务已经停止，隔离浏览器访问游戏时得到连接拒绝。已重新启动仅监听 127.0.0.1 的本地静态预览服务，游戏和素材请求恢复正常。该服务保留供用户继续游玩。

## 2.1 新增并已验证：通关随机掉券

保留全部既有固定奖励，成功通关再额外判定一次：第 1–3 关 25%，第 4–7 关 35%，第 8–10 关 45%，每次一张。重玩可掉，失败不判定。

连续三次通关没有额外掉券后，下次成功通关必掉一张。计数跨关卡保存，失败不清零。概率为非保底局的基础概率，不是计入保底后的长期实际比例。

已用浏览器中的实际结算处理程序完成以下边界检查；这些场景直接设置测试战斗结果，用于测奖励，不伪装成真实通关：

- 三档概率分别在阈值前命中、阈值处不命中，共六个边界通过。
- 连续三次未掉的计数为 1、2、3，第四次即使随机值很高仍发一张，并归零。
- 失败不掉券，也不改变已有的连续未掉计数。
- 首通、首次三星、随机掉落可叠加为三张。
- 重玩时不重发首通 / 首次三星固定券，但可继续随机掉落。
- 同一战斗重复触发结束事件，不重抽、不增加计数、不重复发券。
- 更新后覆盖的页面没有出现游戏脚本异常。

## 隔离与剩余范围

浏览器测试使用独立的无界面 Chrome 和测试上下文；测试券、测试伙伴与测试存档均未写入用户正常浏览器的存档。测试浏览器已经关闭，预览服务继续保留。

本轮没有进行完整手动十关试玩、Windows 独立启动器验证、所有手机触摸设备测试、长时间多标签存档并发或统计随机分布检验。尚未依据结果修改平衡与布局；这些待用户确认后再一并调整。
